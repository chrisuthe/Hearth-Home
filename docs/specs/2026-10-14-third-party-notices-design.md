# Third-Party Notices — Design

**Date:** 2026-10-14
**Status:** Implemented.
**Goal:** Credit the third-party code and content Hearth ships, in the repo and in the app, and keep the list current. Issue #250.

Hearth is MIT. Its builds also ship code and assets under Apache-2.0, BSD-3, OFL, CC BY and LGPL, several of which ask for the licence text or an attribution to travel with the binary. Before this, the only credit was `assets/alarm_tones/CREDITS.md`, and nothing reached the user.

This is our reading of each licence's terms, not legal advice.

## How to read this

- **verified** — the licence was read at its source: the repository's licence file, a file header, or a Maven POM. Where a binary was taken from elsewhere, we compared bytes. The check is named per entry.
- **assumed** — not settled by a source we read. Says what is missing.

## Decisions

The four questions from the issue.

1. **Where credits appear: both.** `THIRD_PARTY_NOTICES.md` at the repo root for people reading the source, and an **Open-source licences** entry in Settings → System on both surfaces. On the device it opens Flutter's licence page (`showLicensePage`). In the `:8090` portal it links to `/licenses`, a page gated by the same session as `/` and `/logs`. Both list `LicenseRegistry`, so they show the same thing: every Dart package plus our notices.
2. **How native and asset licences reach the page: `LicenseRegistry.addLicense`.** `registerThirdPartyLicenses()` runs first thing in `main()` and adds one entry per notice, read lazily from `assets/licenses/` when a licence page first asks. A Gradle licence plugin would cover the Android libraries only, and only on Android; it would leave the fonts, sounds, models, the C code and the Pi with nothing. One mechanism for every platform wins.
3. **How the list stays current: a test.** `test/services/third_party_notices_test.dart` fails when any of these lacks an entry in `assets/licenses/notices.json`:
   - a file under `assets/` (outside `assets/licenses/`);
   - a git submodule (`.gitmodules`);
   - a module under `android/ava/` or `native/`;
   - a fork in `scripts/check-upstream-drift.sh`;
   - a wake-word model in the satellite's asset allowlist.

   It also fails when `THIRD_PARTY_NOTICES.md` is not what the manifest generates, when a licence file is missing or orphaned, or when an entry is malformed. New Android Maven dependencies are not caught; see [Limits](#limits).
4. **Per platform: yes, on the device.** Each entry names the builds it applies to (`android`, `pi`, `linux`, `windows`). The app registers only the entries for the build it is: Android, Windows, the Pi (Linux started with `HEARTH_NO_MEDIAKIT`), or Linux desktop. `THIRD_PARTY_NOTICES.md` lists everything with its platforms.

## Layout

| File | Role |
|---|---|
| `assets/licenses/notices.json` | The source of truth: one entry per credited component, with licence, attribution, source, forks, platforms, the repo paths it covers, and how it was checked |
| `assets/licenses/*.txt` | Licence texts. One copy of each shared text (Apache-2.0, LGPL-2.1); per-holder texts where the copyright line is part of the licence (BSD, MIT, OFL) |
| `THIRD_PARTY_NOTICES.md` | Generated by `dart run tool/gen_third_party_notices.dart` |
| `lib/services/third_party_notices.dart` | Manifest model and Markdown renderer. Pure Dart, so the tool runs under `dart run` |
| `lib/services/third_party_licenses.dart` | Registration with `LicenseRegistry`, platform detection, the portal's HTML |

An entry with `"licenseFile": null` is listed but not registered, because Flutter's package licences already carry it (the GStreamer video player fork is a Dart package).

**Models, checked by bytes.** The `stop` model was the open item in the voice satellite design: its metadata names Kevin Ahrendt, but it is not in `esphome/micro-wake-word-models`. It is byte-identical to the `stop.tflite` asset of release `stop-20241016.2` of `kahrendt/microWakeWord`, an Apache-2.0 repository. `okay_nabu` is byte-identical to release `okay_nabu_20241226.3` there (the copy in the models repo is a later retrain), and `hey_jarvis` to `models/v2/hey_jarvis.tflite` in `esphome/micro-wake-word-models`. All three are now **verified**.

**Not shipped, so not credited.**
- `hey_luna` and the other six Ava models. See the fix below.
- GStreamer and ALSA on the Pi, and libmpv on Linux desktop: installed by the OS package manager, not distributed by us.
- SendspinDroid (MIT): not in the APK yet. Add an entry when #248 lands; the Gradle dependency check in [Limits](#limits) will not catch it.

## Fix: the APK shipped unlicensed models

Building the APK showed all nine of Ava's wake-word models in it, `hey_luna` among them. `android/ava/satellite/build.gradle.kts` took Ava's whole `assets` folder, while the voice satellite design says to bundle three. `hey_luna` comes from a repository with no licence, so we had no right to ship it.

The satellite now copies an allowlist into a generated asset directory: the three sounds, `stop`, `okay_nabu` and `hey_jarvis`. An allowlist means a fork bump that adds a model cannot ship it unnoticed, and the notices test checks the allowlist's models against the credited ones. Ava's `sounds/LICENSE.md` no longer ships; the credit is in our notices instead.

## The fork's README

Apache-2.0 §4(b) asks for a notice on changed files. The fork's `UPSTREAM_PIN` described the `:satellite` move, but its README did not. [chrisuthe/Ava-hearth#2](https://github.com/chrisuthe/Ava-hearth/pull/2) adds a section listing the 80 files moved (unchanged), the files added and the three edited. Hearth's submodule pin is not moved for it; it follows at the next fork bump.

## Limits

- **New Maven dependencies are not caught.** The test reads the repo, not Gradle's resolved graph, so a library added through a Flutter plugin or a fork bump will not fail it. When the Android dependency set changes, rerun `:app:dependencies --configuration releaseRuntimeClasspath` and compare against the Android entries.
- **libmpv and FFmpeg are assumed LGPL.** mpv and FFmpeg are LGPL-2.1-or-later only when built without their GPL parts. We did not read the build configuration of `media-kit/libmpv-android-video-build` or the Windows build. If either enables GPL components, the entry, and possibly the distribution terms of the APK and the Windows build, change. Follow-up.
- **Linux desktop is told apart from the Pi by `HEARTH_NO_MEDIAKIT`**, which the Pi's launch environment sets. A Linux desktop run with it set shows the Pi's notices.
