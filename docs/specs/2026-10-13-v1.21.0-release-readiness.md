## Blocker

The plan was a CI-built Pi bundle of `main`, copied to the Pi by hand. That bundle cannot be produced yet:

- GitHub `chrisuthe/Hearth-Home` `main` is at `35f1514` (`chore: bump version to 1.20.0`), 39 commits behind Gitea `main` at `daa74bf`. It is a plain fast-forward, no divergence (**verified**: `gh api repos/chrisuthe/Hearth-Home/commits/main`, `git merge-base --is-ancestor`).
- The latest GitHub Pi build, the scheduled run [38216135403](https://github.com/chrisuthe/Hearth-Home/actions/runs/38216135403) on 2026-10-12, built `35f1514`, not the commit under test.
- The Gitea Pi workflow (`.gitea/workflows/build-pi-image.yml`) only publishes on a tag; a dispatched run uploads nothing, so it cannot supply a bundle either (**verified** by reading the workflow).

Nothing was pushed to either remote. Either of these unblocks it:

1. Sync `main` to GitHub, then dispatch `build-pi-image.yml` on `main`.
2. Push only the task branch to GitHub and dispatch on that ref, leaving GitHub `main` alone.

Independent of this run: a release cut from Gitea `main` today would tag a commit GitHub does not have. The release process pushes to both, so this resolves itself there, but the Pi's updater reads whichever source `updateSource` names — on this Pi that is `gitea`, not `github` as the task brief assumed.

## Findings

Fixed on this branch:

- Plex timeout test not hermetic on Linux — `0aadecd`.
- Tree dirty after any Android build — `5fb607f`.

Observed, not regressions from the six PRs, not yet filed:

- `DlnaService` logs the cast URL unredacted: `[I/DLNA] Cast: SetAVTransportURI http://…?token=SECRETVALUE123`, while the mpv line for the same URL is redacted.
- After a cast of a URL that fails to open, the renderer still answers `GetTransportInfo` with `PLAYING` / `OK` eight seconds later.
- A cast in portrait is cropped to a centre strip (`BoxFit.cover`); already listed under the orientation spec's portrait follow-ups, now seen on a device.
- `POST /api/config {"dlnaEnabled":true}` on a device that never had DLNA on starts nothing, because the UUID is only seeded by the on-device toggle. Documented in `dlna_plugin.dart`; it means the portal's DLNA switch is a silent no-op on a fresh device.
